| 子阶段 | 名称 | 解决什么问题 | 交付物 |
|--------|------|--------------|--------|

## 3. 设计红线 (全阶段铁律)

1. **LLM 只推理、不执行**: 任何写操作仍必须走 playbook_engine 的 precheck/审批/审计通道, LLM 输出永远不直接拼 SQL 执行。
2. **可降级**: LLM/ES/Embedding 任一组件不可用时, 诊断管道无损回退到现有纯规则路径, 不影响 1-5-10 SLA。
3. **预算受控**: 每次 LLM 诊断有 token 与时间双预算 (默认 30s / 8K tokens), 超预算即截断降级。
4. **全程留痕**: 每次 LLM 调用记录 LLMCallLog (提示词摘要、token、延迟、结果状态), 可审计可回放。
5. **不重构既有骨架**: 只在 diagnosis_pipeline 等既有编排点插入新阶段, 不推翻 Phase 6/7 已验收的结构。

| 指标 | 现状基线 | Phase 8 目标 | 度量方式 |
|------|----------|--------------|----------|
| 根因命中率 | 无度量 | ≥ 70% (人工确认) | RcaFeedback 表统计 |
| 方案采纳率 | 无度量 | ≥ 50% | 处置动作与推荐方案匹配率 |
| MTTR (P1/P2) | 依赖人工 | 下降 30% | Incident SLA 秒表 (t_detect/t_plan/t_resolve) |
| 诊断可用性 | - | LLM 故障时 100% 降级成功 | 演练 (drills) 验证 |
| 案例库自动沉淀率 | 0 (纯人工) | ≥ 80% 已解决事故自动生成案例 | AlertCase 来源统计 |
