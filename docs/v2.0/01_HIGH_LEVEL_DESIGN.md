## 1. 建设背景与系统目标

### 1.1 建设背景
现代企业混合云架构中，异构数据库（Oracle RAC/ADG、MySQL 高可用/TDSQL、PostgreSQL、达梦 DM8、GBase 8a 等）共存，架构复杂度急剧上升。DBA 面临海量告警疲劳、跨组件级联故障定位慢、应急处置高风险等核心痛点。

## 3. 核心子系统划分与职责

### 3.1 深度内核采集子系统 (Deep Collector)
- **多数据源插件化架构**：统一 `BaseDBChecker` 接口标准，向下对接 6 种主流数据库驱动。
- **高低频双通道采集**：
  - **高频通道 (10s)**：采集活跃会话（ASH）、Top 等待事件、Blocking 锁阻塞。
  - **常规通道 (60s)**：采集容量表空间、缓存命中率、连接数、主从同步延迟等。

### 3.2 智能认知与根因分析子系统 (Cognitive RCA)
- **多变量协方差异常检测**：结合周周期 168 时间槽与稳健 IQR，动态调整上下阈值边界。
- **Causal Graph 3.0 因果拓扑图**：将“指标异动、日志报错、变更记录、锁等待”映射为节点，通过传递闭包算法推导出根本原因。
- **LLM Multi-Agent 会诊**：Triage Agent 负责清洗分流，Expert Agent 负责特定内核深挖，生成结构化排查简报。

### 3.3 故障自愈与安全执行子系统 (Auto Remediation & Playbook)
- **Playbook 标准化编排**：涵盖会话熔断、死锁解除、临时表空间释放、参数调优等 30+ 预置剧本。
- **Dry-Run 预演机制**：执行前评估受影响业务连接数、锁释放概率，杜绝误杀误操作。
- **L0-L3 安全放权**：严格区分只读建议（L0）、单人审批（L1）、低危自愈（L2）与高危自动切换（L3）。

### 3.4 DBA 沉浸式交互子系统 (WarRoom & Copilot)
- **Incident WarRoom**：聚合指标、因果拓扑、阻塞树与自愈按钮于单页，杜绝多系统切换。
- **DB Copilot 全局助手**：支持自然语言问答、SQL 改写建议、一键智能体检生成。

## 4. 非功能性需求与高可用设计

1. **性能与高并发**：
   - 支撑纳管 **200+ 数据库实例** 并发采集；
   - 接口平均响应耗时 (P95) ≤ 200ms；
   - 告警触发至前端推达延迟 ≤ 2s (SSE 实时推送)。
2. **安全性与合规**：
   - 所有数据库配置密码采用 **AES-256-GCM** 加密存储；
   - 生产数据库采集账号强制只读权限；
   - 所有运维操作 100% 留存操作人、IP、入参及 SQL 审计日志。
3. **高可用与容灾**：
   - 采集探针具备 5s 强制超时熔断机制；
   - 数据库自监控守护进程（W4 Self-Monitor）实时探活核心组件。
