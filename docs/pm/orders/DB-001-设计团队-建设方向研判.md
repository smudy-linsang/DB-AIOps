- 本单只研判、不写代码。

## 二、交付物

《DB-AIOps 建设方向研判报告》，写入 `docs/pm/reports/DB-001-report-design-team.md` 并直推 main，报告结论必须是「通过 / 有条件通过 / 不通过」三档之一（指研判本身的完成度），并注明未尽事项与风险。

报告必须包含：

1. **v2.6 现状盘点**：已实现能力清单（以代码为准，不以文档为准）；README 中标注的能力逐项核实是真未实现还是文档滞后。
2. **设计稿时效性评估**：仓库根目录与 plans/ 下的下一阶段设计稿（多为 2026-05 的 v2.2 时代产物）逐项判定：已落地 / 部分落地 / 已过时 / 仍有效，引用文件给路径。
3. **候选方向**：提出下一阶段候选方向不少于 3 个并排序，每个方向写明：目标、主要工作量、风险、对银行生产环境的意义。
4. **首攻建议**：建议首攻方向 + 首批任务拆分建议（拆到可派单粒度，不用写代码）。
5. **约束与缺口**：gork-team 11-05 前不可用；GG/C/D 本机开发环境待建；直推 main + validate.sh 纪律对方向选择的影响。

## 三、约束

- 引用仓库内容必须给文件路径；不确定的写“未核实”，不许编数字、编结论。

- 设计团队内部分工由队长 DSMan 定；GG 负责架构与实现可行性一节。

## 四、验收

- 验收后另派 O 独立评审（DB-002），评审通过后方向建议才提交用户拍板。
