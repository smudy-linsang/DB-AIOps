执行：MMMan

## 背景

- O 于 2026-11-18 在 main 上直接落地三批用户体验改进（用户直接交办），提交：`ab79a04`（运维工作台透明度与交互恢复能力）、`4e607c7`（值班队列与可追溯事故交接）、`0e06290`（告警恢复与事故证据闭环）、`c911170`（picomatch 高危漏洞修复回补）。设计说明与验证报告在 `docs/ux/`（EXPERIENCE_DESIGN.md、OPERATIONS_EXPERIENCE_DESIGN.md、OPERATIONS_RELIABILITY_DESIGN.md 及三份验证报告）。
- O 的验证报告为实施者自验证：后端 SIT 各批 622/629/642 项 0 失败、前端 85–97 项通过、浏览器 UAT 11＋10＋9＋21 个流程 0 未捕获异常；但浏览器验收的截图与结果证据在 O 本机（`/workspace/dbaiops-evidence/`），PM 未见。PM 已独立核验 CI：`c911170` 11/11 全绿（方言、集成、前端、安全扫描），代码层面无异常。
- 本单为独立验收：换一双眼睛，在真实浏览器上模拟人类使用，把三批改动从头用到尾，专查页面卡顿、报错、渲染失败。

## 任务

1. **环境**：本机当前 main checkout 起服务（Django＋前端，按仓库脚本走），真实 PostgreSQL 业务库；系统 Chromium 真浏览器，键盘＋鼠标操作；桌面 1440px 与窄屏 390px 两档。
2. **独立设计流程，不只重跑 O 的脚本**：O 的三组验收脚本（`scripts/experience-uat.cjs`、`operations-uat.cjs`、`reliability-uat.cjs`）与种子脚本可作参考，但本轮必须另行设计自己的探索流程，主动试着把它用坏：反复切换窗口、快速连续点击、刷新与返回、断网后恢复、错误输入、越权账号探查。只复跑 O 的脚本不算独立验收。
3. **必查三批范围**：
   - 工作台：各来源状态与更新时间是否真实、失败是否保留旧值而不吞成零；趋势窗口 1/6/24/168 小时切换后数据窗口是否一致、迟到响应是否覆盖新窗口；统计是否只算可见启用实例；全局搜索回车与无结果说明；登录失败就地提示、失效会话登录后是否回原页面及查询/锚点；404、错误页折叠与恢复；纳管改参数是否撤销旧测试结论、未保存关闭是否确认。
   - 值班队列：队列排序、检索、分页、筛选页地址交接；告警确认是否留第一位操作者与首次时间、重复确认是否同一回执；结案对话框目标/影响/原因、取消是否无写请求；系统健康依赖/组件/心跳、巡检 0% 与 0 秒是否如实显示；只读账号是否看不到确认与结案入口。
   - 告警恢复与证据：告警确认后恢复依据是否保留实测值与判据；采集健康正常/过期/失败/从未采/已停用是否分得清；验证报告无判据/缺证据/仍超阈/稳定恢复四态；诊断证据索引、OAM 轨迹分页后定位是否可用。
4. **专查三类问题并逐项记录**：页面卡顿或响应迟滞（写清操作与等待时长）、报错（页面报错、控制台错误、未捕获异常，附请求编号与复现步骤）、渲染失败（空白、错位、溢出、数据显示异常，附截图）。没发现问题也要写清查过哪些流程、每项结果是什么，不得只写“未发现问题”。
5. **验收后清理**：测试账号与合成记录全部清理，恢复环境到验收前状态。
