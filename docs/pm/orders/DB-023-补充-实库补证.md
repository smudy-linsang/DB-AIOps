# DB-023 补充：实库补证

执行：GorkMan

## 背景

- DB-023 已验收有条件通过（STATUS v1.35）：下半 34 项逐项已实现、已登记，映射 91/68/0/65 自洽，CI 7 job 全绿；条件 7 条，主项 Oracle 16 项、DM 4 项、GBase 3 项 SQL 未在对应实库执行，GTID 无官方 MySQL 主从实测；缺陷单为空。
- MySQL 5 项与 PG 6 项已在本机 MariaDB 10.11 与 PostgreSQL 16.15 上执行过（报告 §三），不在本单范围。
- 本单只补外网可测的 DM、GBase 实库证据；Oracle 16 项与 GTID 主从延后。

## 任务

DB-023 报告 `docs/pm/reports/DB-023-report-gorkman.md` §三，下列 7 项 SQL 原文在对应外网实库逐项执行，逐项留实测输出原文：

- DM 4 项——宿主 DM8 服务实库，走 DB-009 已验证的 DM 实库通道：
  - #65 `INS-DM-DSC`：`DSC_NODES` 实测值、`V$DSC_EP_INFO` 明细；形态 skip 须以实测 `DSC_NODES` 为准。
  - #66 `INS-DM-DW-STANDBY`：`V$ARCH_STATUS` 非本地目的地实测状态。
  - #67 `INS-DM-ARCH`：`ARCH_MODE` 实测值与目的地、`V$ARCH_FILE` 计数。
  - #68 `INS-DM-RLOG`：`ARCH_TYPE` 为 REALTIME/TIMELY/RLOG 的 `V$ARCH_STATUS` 实测状态；SQL 不含 `V$RLOG`。
- GBase 3 项——GBase 8a（127.0.0.1:5258）实库，走 DB-009 已验证的 GBase 实库通道：
  - #69 `INS-GBASE-BALANCE`：`gcluster_v$node_info` 的 CPU_USED、MEM_USED 极差。
  - #70 `INS-GBASE-DIST`：`gcluster_v$table_distribution` 按节点汇总 `DATA_SIZE` 的极差；该视图为本项新写，实库若无此视图或视图名不同，检测结果记 error 并如实写明，不得写成均衡。
  - #71 `INS-GBASE-NODE-DOWN`：同一节点视图里状态不含 ONLINE/ACTIVE/HEALTHY/NORMAL 的个数；0 行记 error，不得写成无宕机。
- Oracle 16 项（#36–43、#45–52）：不做，外网无真实库，延至上线后内网复测；报告逐项写明"未测·延后"。
- GTID（#54 `INS-MYSQL-GTID`）：不做，需官方 MySQL 主从；MariaDB 无 `gtid_mode`，延后。

每项写清：SQL 原文、实库（库名/版本/时间）、输出原文、判定。报告 §五其余 5 项（半同步、DBLINK 样本、打开文件数、膨胀率估算、阈值 error 档）为方法口径说明，本单不改方法、不重做判定，只如实引用；是否构成转通过障碍由 PM 在验收时裁决。
