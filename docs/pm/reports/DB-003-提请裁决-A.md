## 事项 1：直推 main 的代码当前不跑 CI

- 现状（已实测）：仓库默认分支是 `master`，黑板与日常直推都在 `main`（`main` 包含 `master`，另有黑板提交）。`.github/workflows/ci.yml` 只监听 `pull_request`/`push` 到 `master`，所以直推 main 的提交不会触发静态检查、单元、集成、方言、安全扫描、前端这 7 项。
- 影响：README「推完回头看一眼 CI」在 main 上落空，本地 `scripts/validate.sh` 成了唯一的闸。
- 可选方案：
  - A. 把默认分支改为 `main`，同时把 `ci.yml` 的 `branches: [master]` 改成 `[main]`（或两者都列）。好处：一劳永逸，与 README 的「直推 main」一致。代价：需要用户在 GitHub 设置里改默认分支，`master` 后续定位需另定（冻结或删除）。
  - B. 保持默认分支 `master`，只把 `ci.yml` 改成同时监听 `main` 与 `master`。好处：改动最小。代价：「事项 2」的兜底仍不生效；两条主线并存，易混淆。
  - C. 维持现状，在 README 写明「main 上无 CI，以本地 validate.sh 为准」。
- A 的建议：**A**。
