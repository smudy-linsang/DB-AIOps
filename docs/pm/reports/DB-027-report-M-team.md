## 五、缺陷清单（7 条）

### D-01【中·功能不可用】告警中心「详情」按钮点击必然抛未捕获异常，告警详情抽屉打不开

- **范围**：frontend/src/pages/AlertList.jsx:149
- **根因**：列定义处于模块作用域，其 render 函数引用了作用域外的 onView（真实 handler 在同文件 L277 以 tableProps.onView = setDetailAlert 传入），点击时 onView 未定义 ⇒ ReferenceError。属事件处理器内抛错，**不经过 ErrorBoundary**，页面不崩但功能失效、控制台留未捕获异常。
- **复现步骤**：① 打开 /alerts（告警中心）；② 点任意一行右侧「详情」按钮；③ 观察：抽屉未打开（.ant-modal/.ant-drawer 数量均为 0），且未发出任何详情请求；④ 控制台出现未捕获异常。
- **控制台日志**（原样）：

    error> Uncaught ReferenceError: onView is not defined
    ### Stack trace
    at  (AlertList.jsx:149:70)

  该异常本轮累计出现 4 次，对应 4 次点击；另有 Failed to load resource: 401 4 次系本轮探针自身未带 Authorization 头所致，**非产品缺陷**。
- **截图**：F18-alert-list.png（列表与详情按钮）、F21b-alert-detail-view.png（点击后无抽屉）、F21c-alert-detail-after-click.png。
- **影响面**：告警中心内的**恢复依据（实测值/阈值/判据）无法查看**。★同一证据在**工作队列「查看告警摘要」抽屉可正常显示**（来源 采集器实测 · 指标 qps · 观测值 0 · 阈值 80）⇒ 缺陷限于告警中心入口，非数据缺失。
- **建议**：把列渲染改为接收组件作用域（例：把 onView 经 tableProps 透传到列 render，或列定义改为组件内生成），并补一条前端回归用例覆盖「点击详情」。

### D-02【中·降级不可见】实时推送降级时前端不识别后端 degraded 事件，页面无可见提示

- **范围**：frontend/src/stores/useAppStore.js:92-160（只监听 connected / alert / metric / heartbeat，**未监听 degraded**）
- **根因**：/api/v1/events/ 在 USE_REDIS_CACHE=False 下立即返回 event: degraded 并关闭连接；前端 EventSource 立刻进入 onerror ⇒ 指数退避重连 5 次（1/2/4/8/16 秒）后仅 console.warn 停止，**页面无任何提示**。
- **复现步骤**：① 打开任一页面并等待；② 观察控制台；③ 页面无降级提示，告警角标与实时状态静默失效。
- **接口实测**：GET /api/v1/events/?token=… → HTTP 200，**108 字节即返回**，body：

    event: degraded
    data: {"message": "Redis 未启用，实时事件流不可用（USE_REDIS_CACHE=False）"}

  直连 8009（time=0.003s）与经 3000 代理（time=0.020s）行为一致 ⇒ 断连发生在业务层，不是代理层。
- **控制台日志**：[SSE] 重连次数已达上限，停止重连。实时推送不可用，请刷新页面重试。（warn）
- **截图**：F24-dashboard-1440.png。
- **影响**：与批一「失败要显式说明、不能静默吞掉」相悖；用户对实时推送已失效毫不知情（默认部署即命中该配置）。
- **建议**：前端监听 degraded 事件并直接呈现降级提示（复用既有「系统降级」入口），不再做无意义的 5 次退避重连。
