# DB-AIOps 使用体验改进详细设计

日期：2026-11-18。适用范围：现有 Django / React 平台，不改变数据库采集方言、数据模型和运维审批链。

## 1. 目标、调查与交付边界

用户需要在压力下回答：我在哪里？哪些数据可信？先做什么？操作失败如何恢复？
本次检查项目目录、路由、权限、接口契约、页面交互与测试入口，重点逐段审阅登录、全局布局、仪表盘、数据库纳管、请求处理和对应后端统计/趋势实现。项目包含数百个源文件；不把结构扫描宣称为逐行审计全部采集器。

发现的问题：

| 现象 | 用户影响 | 本次实现 |
| --- | --- | --- |
| 首页各接口 catch 后变空数组 | 故障被理解成没有告警/实例 | 独立来源状态、保留上次成功数据、显式重试 |
| 最后更新时间是渲染时间 | 误以为旧数据刚采集 | 显示请求成功时间，区分刷新和采集 |
| 时间范围按钮不传给 API | 图表标题与数据窗口不一致 | hours 参数贯通并后端校验 |
| 统计读取所有人的评分/告警，ORM 趋势未限范围 | 越权汇总与误导 | 可见、启用实例过滤，今日评分、互斥状态计数 |
| 全局搜索只过滤导航树且无解释 | 找不到功能、回车无反馈 | 有权限的功能/已加载实例即时搜索，空结果解释 |
| 登录后丢失原页面，401 无上下文 | 操作中断 | 安全站内 returnTo、登录错误留在表单 |
| 不存在的路由静默回首页 | 用户不知道链接失效 | 404 和明确返回入口 |
| 渲染异常一上来就是堆栈 | 普通用户难以行动 | 恢复按钮优先、技术详情折叠、切换页恢复 |
| 修改连接参数仍显示旧测试成功 | 误信旧连接证据 | 变更即失效，异步结果版本检查 |
| 关闭纳管表单直接丢失输入 | 重复劳动 | 未保存退出确认，连接测试不等于保存 |

## 2. 交互与实现规格

### 2.1 全局导航与帮助

保留熟悉的菜单；顶部搜索支持功能中文名、路由、数据库名称和主机。功能来源是权限过滤后的菜单；实例来源是服务器已返回的可见实例；不新增越权查询。下拉显示类型，点击/键盘回车导航；无命中说明搜索范围，不承诺搜索 SQL 原文或历史指标。输入不保存凭据。
增加全局“使用指南”抽屉，按“纳管→监控→告警/事故→审批执行→报告”说明入口与权限限制；强调 AI 诊断是建议、连接测试只证明当次连通。移除没有实现的个人中心/系统设置假入口。移动窗口顶部换行、内容收缩，菜单可折叠，按钮有可访问名称。

### 2.2 数据真实性

仪表盘一次刷新并行获取健康检查、实例列表、活跃告警、趋势和统计；使用 allSettled 隔离失败。来源逐项说明“已更新/未获取/失败保留旧数据”，失败带可用的请求编号；不显示响应正文、凭据。初次失败的总数显示“—”，不能显示零；真实空列表提供纳管入口。更新时间只在该来源成功后推进。

趋势窗口为 1/6/24/168 小时；后端仅接受整数 1..168，错误 400。响应增加 source、hours、generated_at、aggregation，说明是小时内样本均值而非总 QPS。窗口切换时旧趋势清空、过期异步响应丢弃；刷新互斥，卸载后不更新状态。CPU 没有后端数据则不提供选择。健康分缺失显示“未评分”，不能渲染为零分。

后端 stats 仅统计 visible_to(user) 且启用的真实实例；DOWN/DEGRADED/UNKNOWN 不重叠；仅使用今日健康分，返回 scored_count；活跃告警同样限实例范围。ORM 与 TimescaleDB 两条趋势路径共享可见实例 id，空范围不扩大到全部实例。降级必须日志留痕，ORM 也失败则 503，不能返回伪正常空图。

### 2.3 认证与失败恢复

401 清理失效会话并携带当前 path+query+hash 到登录页；登录成功 replace 回到安全相对路径；拒绝 //、反斜杠、外站和 /login 防循环。登录失败就地提示且保持用户名，密码提供自动填充语义。共享 API 把 message/status/code/requestId 归一化，取消请求不重试；写操作不自动重试。

未知页面展示 404；403 保留联系管理员说明。错误边界更换路由时清零；默认不展开堆栈，提供重试/刷新。

### 2.4 纳管表单

连接测试与配置保存各自反馈，字段变动立即撤销此前测试结果；用版本号拒绝旧参数的晚到测试结果。关闭按钮/取消/遮罩统一走未保存确认；保存中不允许关闭。密码仍只发给现有加密配置接口，不能写 localStorage 或日志。错误使用归一化后的 message，不再吞掉后端解释。

补充发现与设计：新增纳管保存必须持久化用户选择的采集周期与模板，前后端统一校验 10..3600 秒；保存失败不能丢失表单。由创建 API 集成回归和真实浏览器添加/回读验收。

## 3. 科学有效性自评

| 设计依据 | 可证伪的验收指标 | 风险与控制 |
| --- | --- | --- |
| 系统状态可见性 | 失败不出现“0 告警正常”；更新时间不凭渲染推进 | 部分成功可能混合时间，因此逐来源标时间 |
| 识别优于记忆 | 输入“事故”可直接找到入口 | 搜索按权限过滤且声明实例缓存范围 |
| 错误预防 | 改连接字段后旧成功消失，取消不直接丢表单 | 版本检查处理竞态 |
| 用户控制与恢复 | 登录回原页；404 有出口；异常不锁住别的页 | 只允许站内跳转 |
| 最小权限与可解释统计 | 隐藏库极端指标不能改变本用户结果 | 分别验证零权限和有权限但限范围 |

自评结论：这些改动具备明确因果机制、可重复测试与低迁移成本；不宣称已经证明真实用户满意度或缩短 MTTR，后续需真实 DBA 可用性研究。本次 UAT 是代理执行的浏览器验收，不能代替业务负责人签字。

## 4. 验证、部署和回滚

每批代码修改立即运行 scripts/validate.sh unit --json；完成后运行前端构建/全量组件测试、真实 PostgreSQL 后端全量测试、迁移漂移/依赖/红线检查。新增回归覆盖统计隔离、错误窗口、来源失败、登录跳转、连接测试失效和退出确认。

真实 Chromium 中以键盘/鼠标完成登录、导航搜索、范围切换、刷新、空态、错误与重试、纳管输入/修改/取消、404、窄窗口。正常场景使用实际 Django API；故障场景允许浏览器注入网络失败但明确标记，不伪造生产成功。记录截图和断言，失败必须修复并重测。

外部六种目标数据库、真实大模型、邮件/企业通知、生产容量与长稳为独立验收环境要求；本次不启动真实修复或破坏性演练。无需模型迁移；回滚本次源文件即可恢复原行为。
