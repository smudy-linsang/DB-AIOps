# DB-AIOps 运维闭环与证据可靠性设计

本次从告警观测、事件交接、执行再验证三个阶段完善现有值班体验。始终以持久化业务记录、真实采样或已有标准 API 为依据。

| 项目 | 契约与实现 | 可验证标准 |
| --- | --- | --- |
| 告警生命周期 | 保留旧接口的 active、acknowledged、resolved。单独存首次确认人和时刻，监控是否仍异常可独立计算。恢复保存结构化依据。数据库限制同实例、同告警类型、同指标最多一条未恢复记录。存量冲突保留最新记录，其余标为合并，不补编造的恢复时间。 | 触发、确认、持续异常、恢复、再触发。重复确认不覆盖回执，旧历史仍可读。 |
| 数据新鲜度 | 最后尝试和最后成功分别显示。活动实例按最近成功和配置周期分类为未采集、失败、过期或正常，保留历史观测。缺项用真实快照和方言预期核心项计算，0 是值。失败只暴露归类，不回传原始错误或凭据。 | 旧 UP 不再显示为当前正常，失败不能用旧记录或零指标冒充成功。 |
| 事故交接 | 事故提供持久化负责人和下一步，记录更新时间与操作人，原有权限与可见实例约束生效。同实例同时间窗的指标、原始事件、告警、变更和结构关联的工单可查看，时间相邻的记录明确标为关联线索。 | 刷新、跨账号、回链皆可复现同一上下文。不同实例记录不得混入。 |
| 恢复验证 | 验证动作后读取真实采样。使用唯一采样时间去重，缺失值打断连续通过。存窗口、判据、已见和缺失证据、最近值、达到稳定的次数及复发。无判据、未验证、持续异常、证据不足和通过用明确状态。 | 同一份成功数据重复轮询不能使事故解决；未获数据不伪造为不恢复或恢复。 |
| AI 核查 | 固化诊断当时提供给模型的证据索引。只解析包内已知引用；显示来源、采样时间或时刻未知、匹配线索、异议、额外假设、补证项。没有持久化索引的旧报告明确显示无法解析。 | 模型自造的引用或已裁剪证据不可伪装成真实证据；真实资源从事故权限和时间窗口中复核。 |
| CI 与实库 | 维持前端审计门槛；构建与测试独立报告。MySQL、PostgreSQL 的实库方言任务新增采集—确认—恢复验收。 | 审计有正式结果，实库测试要断言采集、业务库告警状态、重发和恢复证据；配置错误时任务失败。 |

系统不会用故障后的回退数据篡改历史。部署先停止旧告警写入进程，运行迁移，随后启动同版本 API 和采集进程。上线观察业务库约束冲突、指标缺采率和恢复误判。数据迁移保留历史记录，回滚前备份并确认旧程序能理解合并记录。以可复现实验验证因果机制，真人值班效率另用实际值班任务计时评估。
