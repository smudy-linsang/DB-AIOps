# DB-AIOps 值班与交接体验详细设计

基于已发布版本 `ab79a04`。本轮目标是让值班人员能快速确定待办、说明判断依据，并把当前上下文交给下一班。

## 审阅与问题归纳

全量逐行自动扫描覆盖 538 个 Git 跟踪的源码、脚本、迁移和配置文本，共 153,449 行，包含旧静态产物和测试代码。扫描定位异常吞没、零值默认、状态反馈、分页、权限和请求编号。对前端导航、事故和告警页面、权限映射、API、数据模型、采集到告警状态流、巡检和自监控等影响本方案的入口另作人工逐段审阅。自动扫描结果是候选位置，不能等同于人工逐行语义审阅。可逐文件核对的路径、行数、哈希和候选行号存于本轮证据目录。

| 用户任务 | 现有缺口 | 本次设计 |
| --- | --- | --- |
| 开始值班 | 事故列表和告警中心分散，固定上限容易被误读为全部 | 首页、导航、使用指南接入值班队列 |
| 处理突发故障 | 新近记录排在旧严重记录前，缺少优先顺序解释 | 服务器按优先级或严重程度、发生时刻、唯一键排序 |
| 交接 | 搜索和筛选丢在页面状态里 | URL 保存类别、阶段、关键词、页码 |
| 判断是否存在任务 | 报错和真正为空缺少明显区分 | 首次加载、当前数据、刷新失败保留旧数据、空、失败分别呈现 |
| 查看及关闭事故 | 详情失败持续“加载中”，关闭立即写入且没有用户说明 | 明确详情、时间线错误，关闭前展示目标并要求原因，显示确认回执 |
| 运维自查 | 系统健康双请求失败可显示空和零降级，缺少尚未上报组件 | 独立错误恢复，展示检查时间、组件汇总与心跳实例 |
| 巡检解读 | 0% 覆盖可被替换为 100%，缺少分数时呈现为零 | 用空值语义显示未知，保留真实零 |

## 值班队列

入口 `/work-queue`，继续提供原有事故中心、告警中心和排障作战室入口。事故默认“待确认”，告警默认“待确认”，括号内各状态计数使用同一关键词和实例范围。阶段为待确认、已确认或已知晓、已结束、全部。事故以 `acked_at` 为准，兼容只有 `acked_by` 的旧记录。已解决和关闭属于已结束。告警使用持久化状态；已确认仅表示曾知晓，实际恢复以恢复时间和现有告警流程为准。展示源为平台业务库，不混用 Elasticsearch 搜索索引。事故和告警各自分页且不对同一事件做猜测合并。队列不执行运维动作。

`GET /api/v1/work-queue/` 需要 `alerts.view`。通过 `DatabaseConfig.objects.visible_to(user)` 隔离行与汇总，包含已停用实例的历史记录。参数为 `kind=incidents|alerts`、`stage=pending|acknowledged|finished|all`、`q`（最多 100 字符）、`page`（正整数、最大 100000）。页大小 20，超出尾页回到实际末页。无效参数返回 400。返回可见阶段计数、所选阶段总数、实际页码、来源、生成时刻与最小展示字段；不返回密码、SQL、运行参数、AI 推理或外部诊断资料。计数来自一个聚合查询，列表另读一次，分页受并行写入影响，按需刷新可收敛。静态数据下每行有稳定排序与分页位置。告警摘要提供标题、实例、发生时间、记录状态及描述，可跳到原告警中心。事故详情链接带同站队列地址，返回后恢复条件。

## 事故确认、结案与系统健康

事故确认仍调用既有 API，服务器原子地保留第一位确认人和首次确认时间。重复提交回同一回执，关闭状态保持原有冲突语义。结案表单提供目标、影响和必填原因，查询失败、操作失败有独立反馈。早先调用方可继续省略原因；显式非法原因明确 400。时间线加载失败时保留事故主体，不把失败显示为暂无事件。动作按钮使用对应权限，所有写操作仍由服务器校验。

顶部系统健康入口支持键盘操作，概要请求失败时仍可进入详情。健康页分别呈现系统概要和组件明细的取数状态。健康概要提供首次心跳缺失、失联和依赖探测，汇总请求失败时不用零值描述系统。已有成功数据在刷新失败时带时间戳展示。巡检页面用空值判断评分、覆盖率和耗时。

## 科学有效性自评与验收

| 设计依据 | 可证伪的验收要求 |
| --- | --- |
| 识别优于回忆 | 默认入口显示待确认事项，用户可用键盘提交检索并打开详情 |
| 状态可见 | 统计与页内结果可核对；故障与空列表文案不同；系统健康明示缺失心跳 |
| 可恢复 | 返回键和刷新保留筛选，网络恢复后一次重试能重载，迟到请求不覆盖新条件 |
| 最小权限与数据可信 | 有权限的受限账号看不到范围外条目及汇总；零权限请求 403；重复确认保持首次回执 |
| 防误操作 | 结案取消没有写请求，用户填写原因后才提交 |

使用 PostgreSQL 的集成测试与真实 Chromium 的 UAT 分别验证数据语义和用户可完成性。用户效率改善仍需真人 DBA 样本验证，不能从测试通过率推断 MTTR 或满意度变化。开发环境使用本地合成告警与事故，不触发真实修复、故障注入或外发通知。

新增只读接口和页面无需迁移。原告警和事故接口保留兼容。后续深化建议包括统一工单和剧本执行凭据链、性能窗口跨页关联、告警确认与恢复状态建模。这些需要独立的业务语义和真实外部集成验证，不纳入本次设计实施清单。
