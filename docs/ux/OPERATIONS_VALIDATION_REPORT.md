# 值班与交接体验交付报告

2026-11-18。基线为已发布版本 `ab79a04`。详细设计和可证伪的验收标准见 [OPERATIONS_EXPERIENCE_DESIGN.md](OPERATIONS_EXPERIENCE_DESIGN.md)。

## 已落地的使用体验

- 从仪表盘、功能菜单、全局搜索或使用指南打开值班队列。事故和告警按优先级排序，分页和状态计数由后端生成。值班人员可以用标题、实例名或编号检索，并把当前筛选页通过浏览器地址交接给同事。
- 空列表、首次失败和刷新失败分别展示。刷新失败时，页面保留同一查询的上次结果并提供请求编号。筛选变化取消旧请求。队列的事项和汇总使用同一实例可见范围。
- 告警摘要展示记录状态和恢复时间。事故确认保留第一位操作者与首次时间，重复确认返回同一回执。结案对话框展示目标、影响和原因，取消没有写请求。可从详情返回原队列页，或在时间线核对结案原因。
- 从顶部进入系统健康，分别查看依赖、组件汇总和实例心跳。请求中断时单独指出失败来源，说明首次缺失的心跳。巡检保留实际的 0% 覆盖率和 0 秒，未评分单独标识。

## 自评与边界

优先级排序和可恢复筛选有明确的交接价值。权限、错误和确认回执有可重复的反例，SIT 与 UAT 均已验证。仍需真实值班人员的任务计时和访谈，才能量化效率或满意度。当前验证未覆盖生产容量、六种目标库的完整采集矩阵、真实通知和外部大模型。

本轮没有模型迁移。安装和运行沿用已发布版本的开发环境，在当前工作区完成。GitHub 依赖审计的基线问题仍未处理。环境配置草稿和已发布环境保持本轮开始时的状态。

## 复跑和证据

在已启动的本地服务上运行以下命令。运行脚本只生成本地随机测试账号与合成记录。

```bash
cd /workspace/DB-AIOps
set -a
source /workspace/dbaiops-runtime/runtime.env
set +a
.venv/bin/python scripts/seed-experience-uat.py
.venv/bin/python scripts/seed-operations-uat.py
trap '.venv/bin/python scripts/seed-operations-uat.py cleanup' EXIT
node scripts/operations-uat.cjs
```

脚本使用 `/usr/bin/chromium` 和现有 Playwright。当前实例证据目录 `/workspace/dbaiops-evidence/v2/` 包含逐文件扫描、浏览器结果 JSON、桌面及窄屏队列和系统健康截图。
